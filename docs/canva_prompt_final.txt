SLIDE 3 — Feature Engineering & Tiền xử lý
================================================================================
Title: "Giải pháp dữ liệu — Feature Engineering từ raw → 17 features"

Sơ đồ flow ngang 3 khối (dùng shapes và arrows):

KHỐI 1: RAW DATA (3 file CSV)
  linkedin_job_postings.csv | job_skills.csv | job_summary.csv
  → JOIN bằng job_id → 1.3M rows

KHỐI 2: FEATURE ENGINEERING (biến đổi từng cột)
  job_title:
    → it_domain (8 ngành): keyword map — "Software Engineer"→Software Engineering...
    → seniority_level (4 cấp): regex — /Senior|Lead|Sr/i→Senior, /Junior|Entry|Associate/i→Junior, /Manager|Director/i→Manager, else→Mid
    Lý do: cột job_level gốc chỉ có 2 giá trị ("Mid-Senior","Associate") — không đủ chi tiết

  job_skills (mỗi skill map vào 1 bucket):
    → 9 binary features: skill_programming, skill_cloud, skill_ai_ml, skill_database, skill_devops, skill_framework, skill_data_engineering, skill_security, skill_soft_skills
    → num_skills = tổng số skill
    → skill_diversity = số bucket khác nhau

  location:
    → state (50 US state codes): trích "ST" từ "City, ST"

  Tự tạo (Interaction features):
    → domain_seniority = it_domain + "_" + seniority_level
    → state_seniority = state + "_" + seniority_level

KHỐI 3: TIỀN XỬ LÝ
  Lọc IT jobs: giữ 8 domain IT → loại non-IT → 180K rows
  Xử lý outlier lương (IQR method):
    Q1=25%, Q3=75%, IQR=Q3-Q1
    Lower = max(Q1-1.5×IQR, $15K) | Upper = min(Q3+1.5×IQR, $500K)
    ~50K→~30K rows (loại 40% outlier)
    Tại sao IQR? Lương phân phối lệch phải, không hình chuông — IQR robust hơn Z-score

KẾT QUẢ: 128,307 IT jobs, 17 features, 30,039 rows có salary (sau IQR)

SLIDE 4 — Giải pháp Pipeline ML
================================================================================
Title: "Pipeline tự động — StandardScaler + OneHotEncoder → 3 Models"

Visual: pipeline flow chart 3 khối nối tiếp

KHỐI 1 — ColumnTransformer (tiền xử lý tự động):
  10 numeric features → StandardScaler (z = (x-μ)/σ — đưa về cùng scale)
  7 categorical features → OneHotEncoder (biến chữ thành vector binary — tránh quan hệ thứ tự ảo)
  Output: ma trận ~120 cột

KHỐI 2 — 3 Model song song:

  Salary (RandomForest/XGBoost):
    GridSearchCV: 12 tổ hợp tham số (n_estimators, max_depth, min_samples_leaf)
    RF thắng: max_depth=25, min_samples_leaf=3, n_estimators=400
    XGBoost thử: n_estimators=500, max_depth=8, learning_rate=0.05, subsample=0.8

  Demand (RandomForest):
    300 trees, max_depth=15
    Input: groupby(domain, state, seniority, job_type) → count → log1p → scale 0-100

  Cluster (PCA → KMeans):
    PCA giảm 120→5 chiều, giữ 79% variance (giải quyết curse of dimensionality)
    KMeans K=5 (Elbow + Silhouette >0.5)

KHỐI 3 — Output:
  Salary → predicted_salary (USD)
  Demand → demand_score (0-100) + interpretation (High/Medium/Low)
  Cluster → cluster_id (0-4) + description

Title: "80% học — 20% thi — Số liệu cụ thể từng model"

MODEL SALARY:
  Dataset: 30,039 rows (sau IQR outlier removal)
  Train: 24,031 rows (80%) — model học từ đây
  Test:  6,008 rows (20%) — model chưa thấy, dùng để tính R² và MAE
  random_state=42: seed cố định → chia lại y hệt mỗi lần chạy
  shuffle=True: trộn trước khi chia, tránh bias thứ tự dữ liệu

MODEL DEMAND:
  Dataset: ~2,300 groups (groupby domain×state×seniority×job_type)
  Train: ~1,840 groups (80%)
  Test: ~460 groups (20%)

MODEL CLUSTER:
  Dataset: 30,039 rows (toàn bộ, không cần test vì unsupervised)
  Dùng 100% data để học cấu trúc cụm

Tại sao 80/20?
  Quy tắc Pareto: 80% đủ để RF/XGBoost hội tụ. Với 24K mẫu, thêm dữ liệu không cải thiện đáng kể R².
  20% (6K mẫu) đủ để đánh giá tin cậy — confidence interval hẹp.

─── PREDICTION ───────────────────────────────────────────────────

POST /api/predict_salary
  Input: {it_domain, seniority_level, job_type, state, 
          skill_programming, skill_cloud, skill_ai_ml, ... (9 skills),
          num_skills, skill_diversity}
  Process: validate input → map vào correct categories → model_registry.salary_model.predict()
  → Pipeline tự động: StandardScaler + OneHotEncoder → RF predict
  Output: {predicted_salary: 165230.00, currency: "USD", period: "Annual"}
  Error handling: 400 nếu input sai format, 503 nếu model chưa load

POST /api/predict_demand
  Input: {it_domain, state, seniority_level, job_type}
  Process: validate → model_registry.demand_model.predict()
  Output: {demand_score: 73, max_score: 100, interpretation: "High"}
  Interpretation: >75=High, 40-75=Medium, <40=Low

POST /api/cluster
  Input: {it_domain, seniority_level, job_type, state, skills... (giống predict_salary)}
  Process: validate → model_registry.cluster_model.predict()
  → Pipeline: StandardScaler + OneHotEncoder → PCA(5) → KMeans(5)
  Output: {cluster_id: 3, description: "Cluster 3: Software Engineering / Senior / Avg $165K (8032 jobs)"}
  Cluster descriptions đọc từ cluster_meta.joblib

─── CV PARSER ────────────────────────────────────────────────────

POST /api/upload_cv
  Input: file PDF/PNG/JPG (multipart form)
  Process: 
    1. Validate file type (pdf, png, jpg, jpeg)
    2. Lưu file tạm → trích text (pdfplumber cho PDF, easyocr cho ảnh)
    3. Regex quét kỹ năng từ text → map vào 9 skill buckets
    4. Suy luận seniority từ title/cấp bậc trong CV
    5. Gọi salary_model.predict() với features đã trích
    6. Xóa file tạm
  Output: {skills: ["Python","SQL","AWS"], seniority: "Senior", 
           predicted_salary: 165000, currency: "USD"}
  Error handling: 400 nếu file sai định dạng, 500 nếu OCR lỗi

─── REALTIME ─────────────────────────────────────────────────────

GET /api/realtime/report
  Process:
    1. Kiểm tra cache (data/realtime_cache.json, TTL=1h)
    2. Nếu còn hạn → đọc cache
    3. Nếu hết hạn → gọi provider chain: freehire.dev → RemoteOK → cache cũ → snapshot
    4. Mỗi provider có IT filter (3 lớp: exclude → include → tech tags fallback)
    5. Tính analytics: top_skills, hiring_velocity, comparison, emerging roles
    6. Lưu cache mới
  Output: {source: "freehire.dev", total_jobs: 16, top_skills: [{name:"Python",count:12}...],
           hiring_velocity: {daily_counts: {...}, avg_per_day: 2.3},
           comparison: {historical_top: [...], realtime_top: [...], conclusion: "..."},
           jobs: [{title, company, location, skills, date}...],
           emerging_roles: [...], cached_at: "2026-07-16T01:55:00"}

GET /api/realtime-trends
  Process:
    1. Đọc data/backup_trends.csv (30 tháng, Kaggle baseline + noise)
    2. Gọi trend_service.build_realtime_report() lấy current_job_count
    3. Scale API count: scaled = api_count × (historical_avg / current_api_avg)
    4. PolynomialFeatures(degree=2) + LinearRegression → fit 30 tháng
    5. Predict 2 tháng tiếp theo
  Output: {status: "success", source: "kaggle+realtime",
           historical: [{month:"2024-01", job_count:128307}...], (30 items)
           forecast: [{month:"2026-08", job_count:132450}...]} (2 items)

  class Registry:
      salary_model = None  # Pipeline object
      demand_model = None
      cluster_model = None
      salary_meta = {}
      demand_meta = {}
      cluster_meta = {}

  def load_all():
      # Gọi 1 lần khi Flask startup
      joblib.load('models/best_salary_model.joblib') → Registry.salary_model
      joblib.load('models/demand_model.joblib') → Registry.demand_model
      joblib.load('models/cluster_model.joblib') → Registry.cluster_model
      # + load 3 meta files
      # Nếu file không tồn tại → log warning, model=None

  Các router gọi: get_salary_model(), get_demand_model(), get_cluster_model()
  → KHÔNG cần load model mỗi request → response nhanh (micro giây)
